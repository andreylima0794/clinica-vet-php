1. Resumo da evolucao

A versao atual continua o Trabalho 1 e reorganiza o sistema para uma arquitetura orientada a objetos. A mudanca principal foi retirar a responsabilidade de acesso a dados dos modelos antigos, criar entidades de dominio e concentrar consultas SQL em repositorios.

6. Fluxos para demonstrar

Fluxo A: login

  1. O navegador acessa GET /.
  2. public/index.php inicializa Composer/sessao e entrega a rota ao Router.
  3. O Router chama AuthController::showLogin, que renderiza Views/auth/login.php.
  4. O formulario envia POST /login; AuthController::login usa Auth e UsuarioRepository::findByEmail.
  5. Database fornece PDO; o repositorio consulta MySQL e retorna Entity\Usuario.
  6. Se correto, a sessao e criada e o usuario e redirecionado; se incorreto, o controller usa feedback e retorna ao login.

Fluxo B: cadastrar ou editar um tutor

  1. GET /tutores/novo ou GET /tutores/editar/5 chega ao Router; no segundo caso, {id} vira parametro.
  2. TutorController busca um Tutor no TutorRepository e renderiza o formulario.
  3. O POST cria os dados recebidos e chama TutorValidator::validar, que usa Validator e checa CPF duplicado.
  4. Se houver erro, o controller envia erros para a view. Se estiver valido, cria/atualiza a Entity\Tutor.
  5. TutorRepository executa SQL preparado via PDO, o controller grava mensagem flash e redireciona para /tutores.
Frase-chave para a apresentacao: “Controller coordena; Validator verifica; Entity representa; Repository persiste; View apresenta; Router conecta a URL ao controller; Database fornece PDO.”
